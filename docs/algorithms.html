Algorithm principles 算法原理详解

This page explains the idea, the exact implementation in this repository, the pseudocode and the cost of every routing stage — from RR-graph modeling to the parallel PathFinder negotiated router. Measured numbers appear on the home page. 本页解释本项目每一个布线阶段的思路、具体实现、伪代码与复杂度——从 RR 图建模一直到并行的 PathFinder 协商布线器。实测数字见主页。

1 · Problem & RR-graph modeling1 · 问题与 RR 图建模

Given a placed FPGA design, routing connects the source of every net to all of its sinks using only available routing resources. This is not a single shortest-path problem: many nets compete for the same limited wires, so a route that is short for one net can block several others. The task is therefore to build a connected sub-graph per net such that no resource is over-used. 在布局完成之后，布线要把每条线网的 source 与全部 sink 连接起来，且只能使用可用的布线资源。它不是单条最短路问题：多条线网会争抢有限的导线资源，一条对自身很短的路径可能堵死其它线网。因此任务是为每条线网构造一棵连通子图，同时保证没有资源被过度占用。

The fabric is modeled as an N×N tile grid, and every tile contributes three kinds of RR nodes. Edges (connections) represent programmable switches between nodes. 布线资源被建模为 N×N 的 tile 网格，每个 tile 提供三类 RR 节点；节点之间的边（connections）表示可编程开关。

H_WIRE

Horizontal wire segment. Used for horizontal travel and horizontal line extensions.

水平导线段，用于水平走线与水平方向的线搜索扩展。

V_WIRE

Vertical wire segment. Used for vertical travel and vertical line extensions.

垂直导线段，用于垂直走线与垂直方向的线搜索扩展。

CB_WIRE

Connection block / logic pin. The source/sink of a net and the turn point between horizontal and vertical wires.

连接块 / 逻辑引脚，是线网的 source/sink，也是水平与垂直导线之间的转向点。

Occupation is stored directly on the node: RRNode::net is nullptr when free and points to the owning net otherwise. A net's path is a list of RR nodes; finalizeRouting() marks them as used. This simple representation is what makes the three detail routers interchangeable: they only differ in how they search for a path, not in how a path is stored. 资源占用直接记录在节点上：空闲时 RRNode::net 为 nullptr，否则指向占用它的线网。线网路径是一串 RR 节点，finalizeRouting() 把它们标记为已占用。正是这种简单表示让三种详细布线器可以互换：它们的区别只在“如何搜索路径”，而不在“如何存储路径”。

Overlap is allowed between nets during negotiated routing. In the PathFinder stage, several nets may temporarily share a node; a node is only judged congested when occ(v) > cap(v).

协商布线允许线网之间临时重叠。在 PathFinder 阶段，多个线网可以暂时共用一个节点；只有当 occ(v) > cap(v) 时才判定为拥塞。

2 · Global routing · sortNets2 · 全局布线 · sortNets

Global routing decides in which order nets are routed. The intuition is that a net whose terminals are packed inside a small region is easily surrounded and blocked by later routes, so it should be routed early. The heuristic measures, for each net, how many global pins fall inside its bounding box (BBOX): the more crowded the box, the higher the priority. 全局布线决定线网的布线顺序。直觉是：端点在空间上越紧凑的线网越容易被后续线网包围、堵死，因此应优先布线。该启发式统计每条线网的 bounding box（BBOX）内落入了多少个全局引脚：box 内越拥挤，优先级越高。

sortNets

O(P log P + Σ kn)

All pins are collected into one pool and sorted by x. For a net, the x-range of its BBOX is located with binary search, then the y values inside that range are counted. Nets are sorted by this count ascending. The strategy is currently kept as an optional switch (sortNets() is commented out in the default path) for comparison studies.

把所有引脚收集到一个池中并按 x 排序。对一条线网，先用二分找到其 BBOX 的 x 区间，再在该区间内统计 y 坐标落在 BBOX 内的引脚数量；按该计数升序排列线网。该策略目前保留为可选开关（默认路径中 sortNets() 被注释掉），用于对比实验。

# 1. build a global pin pool sorted by x
pins = all source + sink pins of all nets
sort pins by x

# 2. rank each net by BBOX density
for each net n:
    bbox = min/max of n.terminals
    lo = lower_bound(pins.x, bbox.xmin)
    hi = upper_bound(pins.x, bbox.xmax)
    count = 0
    for p in pins[lo .. hi):
        if p.y in [bbox.ymin, bbox.ymax]: count += 1
    n.rank = count

# 3. route the tightest boxes first
sort nets by rank ascending

O(P log P)

Trade-off. Ordering helps most when resources are tight, but it is a global greedy heuristic: a good order for one region may be poor for another. It is complementary to — not a replacement for — the negotiated rip-up/reroute loop.

权衡。顺序策略在资源紧张时收益最大，但它仍是全局贪心：对某个区域的好顺序可能对另一区域并不好。它与协商式 rip-up/reroute 闭环互补，而非替代。

3 · Net decomposition · Kruskal MST3 · 网表拆分 · Kruskal 最小生成树

A multi-terminal net cannot be routed by connecting each sink independently to the source, because that would consume the source's neighbourhood repeatedly instead of sharing branches. The standard decomposition builds a minimum spanning tree (MST) over the terminals, then routes each tree edge as an independent two-terminal problem. 多端线网若把每个 sink 都单独连到 source，会反复消耗 source 周围的资源，无法共享分支。标准做法是在所有端点上构造一棵最小生成树（MST），再把每条树边当作独立的两端问题来布线。

Kruskal MST with Manhattan weights

O(P² log P)

Terminals form the vertices of a complete graph; the weight of an edge is the Manhattan distance between its endpoints. Kruskal sorts all P(P−1)/2 edges, unions components with a disjoint-set (union-find), and stops at P−1 edges. The implementation also checks that exactly P−1 edges were selected — otherwise it throws, catching duplicated or missing edges early.

所有端点构成完全图的顶点，边权为两端点的 Manhattan 距离。Kruskal 对全部 P(P−1)/2 条边排序，用并查集（union-find）合并连通分量，选到 P−1 条边即停止。实现中还会严格检查是否恰好选出 P−1 条边，否则抛异常，从而尽早发现重复或缺失的边。

MST(terminals):
    edges = all unordered pairs (i, j), i != j
    sort edges by manhattan(terminal[i], terminal[j])
    parent[i] = i; rank[i] = 0        # union-find
    tree = {}
    for (i, j) in edges:
        a = find(i); b = find(j)
        if a == b: continue       # would create a cycle
        union(a, b)
        tree.add(i, j)
        if |tree| == P - 1: break
    if |tree| != P - 1: error
    return tree

O(P² log P)

Why Manhattan? It matches the rectilinear grid and is a lower bound on the real path length, so short abstract edges tend to become short physical routes. Since the MST only fixes which terminal pairs are routed, the three detail routers still decide the actual geometry.

为什么用 Manhattan？它与矩形网格一致，也是真实路径长度的下界，因此较短的抽象边通常对应较短的物理走线。MST 只决定“哪些端点对需要布线”，实际几何仍由三种详细布线器决定。

4 · BFS maze routing4 · BFS 迷宫布线

Breadth-first search (Lee's algorithm) explores the RR graph in waves of increasing hop count. Because every edge has unit cost, the first time the sink is reached the path uses the fewest hops. A parent map stores the BFS tree, and the path is reconstructed by walking parents from the sink back to the source. 广度优先搜索（Lee 算法）以“跳数”逐层扩展 RS 图。由于每条边代价相同，第一次到达 sink 时的路径跳数最少。用 parent 映射保存 BFS 树，再从 sink 沿父指针回溯到 source 即可重建路径。

BFS (shortest-hop)

O(V + E)

A node is only enqueued if it is unvisited and free (!isUsed()); this makes BFS a conservative availability checker. It has no cost model, so it cannot avoid a hotspot that is still "free" but about to become congested.

只有“未访问且空闲”（!isUsed()）的节点才会入队，因此 BFS 是一种保守的可用性搜索。它没有代价模型，无法绕开那些“仍然空闲、但即将拥塞”的热点。

BFS(source, sink):
    parent[source] = source; queue = [source]
    while queue not empty:
        current = queue.pop_front()
        if current == sink:
            return reconstruct(parent, source, sink)
        for neighbor in current.connections:
            if neighbor not visited and neighbor is free:
                parent[neighbor] = current
                queue.push_back(neighbor)
    return failure

O(V + E)

Measured. BFS is the most robust default: it passes lg_sparse, large_dense, huge (37 s, 46819 segments) and the tighter W=25 stress case.

实测。BFS 是最稳健的默认方法：在 lg_sparse、large_dense、huge（37 s、46819 segments）以及更紧的 W=25 压力场景下均通过。

5 · A* heuristic search5 · A* 启发式搜索

A* is BFS with a guide. Each node keeps a known cost from the source, g(v), and a heuristic estimate to the sink, h(v) = manhattan(v, sink). The priority queue always expands the node with the smallest f(v) = g(v) + h(v), so the search is pulled towards the sink instead of flooding in all directions. A* 是“带导航的 BFS”。每个节点维护从 source 已知的代价 g(v)，以及到 sink 的启发估计 h(v) = manhattan(v, sink)。优先队列每次扩展 f(v) = g(v) + h(v) 最小的节点，使搜索被拉向 sink，而不是向所有方向泛洪。

A* (Manhattan heuristic)

O(E log V)

Manhattan distance is an admissible heuristic for unit-cost grid moves, so A* returns a shortest path for a single two-terminal problem. Globally, however, the greedy order in which nets consume resources can produce an inconsistent commit — a path that looked free while searching may collide with paths committed earlier or later.

对于单位代价的网格移动，Manhattan 距离是可采纳启发式，因此对单个两端问题 A* 能返回最短路。但从全局看，线网消耗资源的贪心顺序可能导致提交不一致——搜索时看起来空闲的路径，可能与更早或更晚提交的路径发生冲突。

A*(source, sink):
    g[source] = 0; parent[source] = source
    open = min-heap keyed by f = g + h
    closed = empty set
    open.push(source, manhattan(source, sink))
    while open not empty:
        current = open.pop_min()
        if current in closed: continue   # stale: a better g was found
        closed.add(current)
        if current == sink:
            return reconstruct(parent, source, sink)
        for neighbor in current.connections:
            if neighbor used by another net: continue
            tentative = g[current] + 1
            if tentative < g[neighbor]:      # relax, may re-open
                parent[neighbor] = current
                g[neighbor] = tentative
                open.push(neighbor, tentative + manhattan(neighbor, sink))
    return failure

O(E log V)

Measured. A* is the fastest per-pair search and wins on large_dense (2 s vs 3 s). On huge it completes all 2307 connections and passes verification with Segments = 46928 in about 23 s — essentially tied with Mikami-Tabuchi (22 s) and clearly faster than BFS (37 s).

实测。A* 的单对搜索最快，在 large_dense 上 2 s 优于 BFS 的 3 s。在 huge 上完成全部 2307 条连接并通过验证（Segments = 46928，约 23 s），与 Mikami-Tabuchi（22 s）基本持平，明显快于 BFS（37 s）。

6 · Mikami-Tabuchi line search6 · Mikami-Tabuchi 线搜索

Mikami-Tabuchi is a line-search (also called line-probe) router. Instead of expanding node-by-node, it grows fronts from both the source and the sink and tries to reach the target side as quickly as possible. In an FPGA fabric made of long horizontal and vertical segments, a front can jump along a whole straight wire instead of one hop at a time. Mikami-Tabuchi 是一种线搜索（line-probe）布线器。它不再逐节点扩展，而是从 source 与 sink 两端同时生长前沿，尽快与对侧相遇。在由长水平/垂直导线段构成的 FPGA 结构里，一个前沿可以沿整段直线导线前进，而不是一跳一跳地走。

Double-end line search

type-driven expansion

Expansion depends on node type: a CB_WIRE pin expands one step; an H_WIRE or V_WIRE continues straight along neighbours of the same type until the type changes or the wire is blocked. Two parent maps, parentS and parentT, record both trees; a node appearing in the opposite map is the meeting point. The path is the concatenation of the two half-paths.

扩展规则取决于节点类型：CB_WIRE 引脚只走一步；H_WIRE 或 V_WIRE 沿同类型邻居直线延伸，直到类型变化或被阻挡。两棵搜索树分别用 parentS 与 parentT 记录；某节点出现在对侧父表中即为相遇点。最终路径由两段半路径拼接而成。

Mikami(source, sink):
    parentS[source] = source; frontierS = [source]
    parentT[sink]   = sink;   frontierT = [sink]
    meet = null
    while frontierS and frontierT not empty and meet == null:
        frontierS = expand(frontierS, parentS, parentT)
        if meet: break
        frontierT = expand(frontierT, parentT, parentS)
    if meet == null: return failure
    return path(source .. meet) + path(meet .. sink)

expand(frontier, own, other):
    next = []
    for node in frontier:
        for nb in node.connections:
            if nb not traversable or nb in own: continue
            own[nb] = node; next.push(nb)
            if nb in other: meet = nb; return next
            if nb.type in {H_WIRE, V_WIRE}:
                extend straight along same type, adding to next
    return next

O(V + E) worst case, far fewer expansions in practice

Measured. On huge, Mikami-Tabuchi completes verification in 22 s with 46769 segments, versus BFS's 37 s / 46819 segments — about 40% faster and slightly shorter. The straight-wire jumps avoid flooding the grid, which is exactly why line search suits rectilinear FPGA fabrics.

实测。在 huge 上，Mikami-Tabuchi 用 22 s、46769 segments 完成验证；BFS 为 37 s、46819 segments——约快 40%，线长也略短。直线跳跃避免了对网格的泛洪，这正是线搜索适合矩形 FPGA 结构的原因。

7 · PathFinder negotiated routing7 · PathFinder 协商布线

The three detail routers above are all one-shot: once a path is committed it is never reconsidered. PathFinder makes routing iterative. Each round it rips up every net and reroutes it while charging extra for congested resources. Nets that fought over a node are pushed apart in later rounds until the design is conflict-free or the iteration budget is exhausted. 上面三种详细布线器都是一次性的：路径一旦提交就不再改动。PathFinder 把布线变成迭代过程：每一轮先拆除所有线网，再在对拥塞资源加价的前提下重新布线。争抢同一节点的线网会在后续轮次被逐渐推开，直到无冲突或迭代预算用尽。

Negotiated cost function

this repository's implementation

The cost of using node v in round t combines three pressures: a base cost, the accumulated historical cost h(v), a present sharing penalty p(v,t) and an iteration factor that grows with t.

第 t 轮使用节点 v 的代价由三部分压力叠加：基准代价、累计的历史代价 h(v)、当前共享惩罚 p(v,t)，以及随 t 增长的迭代因子。

cost(v, t) = (1 + h(v)) · p(v, t) · (1 + 0.1 · t)

Here h(v) starts at 1.0 and grows by 1 each round in which v was over-used. The sharing penalty is flat when the node was not shared in the previous round; otherwise it grows quadratically with the overflow, which makes the search back off congested nodes quickly.

其中 h(v) 初值为 1.0，只要 v 在某一轮被过度占用就 +1。当上一轮未被共享时共享惩罚为常数 1；否则随溢出量二次增长，从而让搜索更快地避开拥塞节点。

p(v, t) = 1   if v was not shared last round若上一轮未被共享
p(v, t) = 1 + 0.5 · (over + 1)²   otherwise, over = max(0, |prevIterNets(v)| − cap)否则，over = max(0, |prevIterNets(v)| − cap) 
negotiated():
    h(v) = 1.0 for all v
    for t = 0 .. maxiter - 1:
        rip_up_all_nets()
        occ(v) = 0 for all v
        # Phase A: parallel search (h(v) is read-only here)
        parallel for each net n:
            localPath = []
            for pair in MST(n):
                negotiated_astar(pair, t, localPath)
            tempPaths[n] = localPath
        # Phase B: serial commit
        for each net n:
            n.path = tempPaths[n]
            for v in n.path: prevIterNets(v) = {n}
            n.finalizeRouting()
        recordOccupancy()                 # occ(v) = number of nets using v
        if no v with occ(v) > cap(v): return converged
        updateHistoricalCosts()           # h(v) += 1 where over-used
    return unconverged

O(maxiter · (V + E) · N)

Convergence. A round is conflict-free when every node satisfies occ(v) ≤ cap(v); the router then stops early. On med_dense it converges in 35 rounds at W=25 and 39 at W=30, but at W=20 it hits the 50-round limit — the critical width is between 20 and 25. On large_dense and huge it does not converge within 50 rounds; wider channels or more rounds (and a better cost model) would be needed.

收敛判据。当所有节点满足 occ(v) ≤ cap(v) 时本轮无冲突，路由器提前结束。在 med_dense 上，W=25 用 35 轮、W=30 用 39 轮收敛；W=20 则达到 50 轮上限——临界宽度在 20–25 之间。在 large_dense 与 huge 上 50 轮内不收敛，需要更宽的通道、更多轮次以及更好的代价模型。

8 · OpenMP parallelization8 · OpenMP 并行化

A round is split into two phases. Phase A (parallel) routes all nets, each thread writing only to its own thread-local path buffer, so there is no data race. Phase B (serial) commits those buffers into the global resource table, records occupancy and updates historical costs. Routing search is the expensive part and is parallel; state mutation is cheap and stays serial. 一轮迭代拆成两个阶段。Phase A（并行）并行布线所有线网，每个线程只写自己的线程本地路径缓冲，因此没有数据竞争。Phase B（串行）把这些缓冲提交到全局资源表、统计占用并更新历史代价。搜索是耗时大头，并行处理；状态修改开销小，保持串行。

route-in-parallel, commit-in-serial

#pragma omp parallel for schedule(dynamic)

During Phase A the historical cost h(v) is only read, never written, which is what makes the parallel phase safe. Each net's temporary path is written to tempPaths_[i]; the serial commit loop then calls net->setPath(), snapshots the previous-iteration owners with prevIterNets, and calls finalizeRouting(). Occupancy is counted once, serially, after all threads have joined.

Phase A 中历史代价 h(v) 只读不写，这正是并行安全的关键。每条线网的临时路径写入 tempPaths_[i]；串行提交循环再调用 net->setPath()、用 prevIterNets 记录上一轮占用者，并调用 finalizeRouting()。占用统计在所有线程汇合后串行执行一次。

Determinism and speedup. Because the search only reads the previous round's state, the solution is independent of the number of threads: 4, 8 and 16 threads all converge in 35 iterations with Segments = 2970. Wall-clock time falls 7 → 4 → 3 s, i.e. about 2.33× from 4 to 16 threads. The speedup is sub-linear because the serial commit, occupancy and cost-update phases cannot be parallelized (Amdahl's law).

确定性与加速比。由于搜索只读取上一轮状态，解与线程数无关：4、8、16 线程都在 35 轮收敛，Segments = 2970 完全一致。墙钟时间从 7 → 4 → 3 s，即 16 线程相对 4 线程约 2.33×。加速比低于线性，因为串行提交、占用统计与代价更新阶段无法并行（Amdahl 定律）。

Takeaways. (1) A good decomposition (MST) makes each detail router's job well-defined. (2) One-shot routers are fast but can fail after commit, so pairwise optimality is not global optimality. (3) Negotiation fixes that in principle but needs enough channel capacity. (4) Parallelizing the search while keeping commit serial preserves the result exactly.

结论。(1) 好的拆分（MST）让每个详细布线器的任务定义清晰；(2) 一次性布线器快，但提交后可能失败，说明“单对最优”不等于“全局最优”；(3) 协商布线在原理上能解决该问题，但需要足够的通道容量；(4) 搜索并行、提交串行，可以精确保持解不变。
